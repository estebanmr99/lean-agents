# Changelog

All notable changes are documented here. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versioning: [SemVer](https://semver.org/).

## [Unreleased]

### Added

- `--everything` installs `jq` (Homebrew or winget) when you pick the Warp plugin for Claude Code and jq is missing, since the plugin's hooks need it; `--uninstall` removes it (#179).
- `--install-agent opencode-v2` and `--upgrade-agent opencode` install OpenCode 2 on Windows through Git Bash with the pinned installer, and put `~\.opencode\bin` first on the user PATH (removed again by `--uninstall-agent`) (#179).
- Optional install of Warp and Orca terminal apps (`--install-terminal warp|orca|both`, undone by `--uninstall`). Integrations continue to be preselected if the app is already installed.

### Fixed

- OpenCode 2: lean-agents no longer installs the RTK plugin, which rtk writes for the 1.x plugin API and OpenCode 2 refuses to load (#179). Installs from before keep the step on record, so `--uninstall` still removes the plugin; to drop it now, run `rtk init -g --opencode --uninstall`.
- Windows: when Bun is in `~\.bun\bin` but not on PATH, lean-agents now puts that folder on the user PATH (`--uninstall` takes it off again) instead of only warning (#179).
- `--uninstall` on Windows waits for the Orca uninstaller to finish (it relaunches itself and returned at once, so the Orca folder could still be there).
- `--dry-run` and `--update --dry-run` mark an install that is already there (the Orca or Warp app, a vendor checkout) as "already there, skipped" instead of listing its install commands; the real run already skipped it (#179).
- `--doctor` checks Context Mode on the Node lean-agents installed it on, not on PATH (#179 PC run).
- `--doctor` shows why `codeburn runs` / `autoskills runs` failed, with a hint for a broken npx cache entry (#179 PC run).
- `--upgrade-agent opencode` no longer copies local plugin file paths from the 1.x `plugin` list into 2.x `plugins[]`; they are listed as manual (#179 PC run).
- `--install-agent claude` on Windows adds `~\.local\bin` to the user PATH (the upstream installer only prints a note), and `--uninstall-agent claude` removes it (#179 PC run).
- Claude Code installer pin refreshed after an upstream change to install.sh.
- `--uninstall` still tries the undo of a command that had failed (`ok: false`), but its failure no longer keeps the record, so a half install can be uninstalled (#179 PC run).
- On Windows with Node older than 24.20, a skills install or removal that finished no longer counts as failed when Node crashes on exit (nodejs/node#56645), so `--uninstall` can complete (#179 PC run).

## [1.0.0] - 2026-11-18

First stable release. Highlights since 0.8.0:

- **Fresh machine:** `--everything` plans and installs the prerequisites (Node.js, git, Homebrew or winget, nvm) and the full setup from a clean Mac or Windows PC; `install.sh` and `install.ps1` work without Homebrew, Node.js, git or winget. A nightly workflow runs it ([#179](https://github.com/estebanmr99/lean-agents/issues/179)).
- **OpenCode 1.x to 2.x, guided:** `--upgrade-agent opencode` backs up the 1.x sessions to a permanent frozen copy, installs 2.x next to the 1.x binary (`opencode1`), translates the config, and has an undo and a rollback ([#80](https://github.com/estebanmr99/lean-agents/issues/80)).
- **Install by VS Code Copilot agent mode:** a guide, a `--json` summary and the VS Code Copilot adapter in the agent lifecycle ([#180](https://github.com/estebanmr99/lean-agents/issues/180)).
- **Update plan and undo:** `--update --dry-run` shows what moves and the release notes, `--update` also moves the agent CLIs inside a major, and `--update --undo` restores the previous versions ([#182](https://github.com/estebanmr99/lean-agents/issues/182)).
- **Antigravity and Cursor:** Antigravity pilot (IDE and extension detection, proxy variables in `--doctor`), more pins (Antigravity cask, Bun, rtk, uv, gh), and the Cursor installer re-pinned twice.
- **Summary page:** the finish step writes a local HTML page with the log-ins to do, an agent verify prompt and next steps ([#181](https://github.com/estebanmr99/lean-agents/issues/181)).
- **CI:** macOS legs and the slow Windows legs skip pull requests (macOS runs nightly and on dispatch); the release workflow publishes to npm through trusted publishing only ([#160](https://github.com/estebanmr99/lean-agents/issues/160)).
- **Hardening:** eight independent reviews and the 0.8.0 audit are fixed or tracked in [`docs/audit-1.0.0.md`](docs/audit-1.0.0.md).

- `--upgrade-agent opencode --yes` and `--undo [--yes]` (#80 part 2, P6, `scripts/lib/opencode-upgrade.mjs`): apply runs only with a verified backup stamp (`--backup --yes` writes `STAMP.json` last; apply re-hashes the backup against its manifest and checks that the live data equals the backup or the frozen copy), refuses while any `opencode` process runs, then runs five journaled steps in `state.json` `upgrade`: `backup` (verify), `opencode1` (P4), `install2x` (the pinned installer, or a 2.x already there; the installer may overwrite the 1.x binary at `~/.opencode/bin`, the copy from the step before is the way back), `config` (P5 translation and managed items) and `dcp` (P5). Apply never opens or starts OpenCode 2 and only reads the live data. A failed step undoes the finished ones in reverse (each step with its own fsops backup folder); if the live data changed meanwhile it is restored like `--undo`; if a rollback step fails it stops, keeps the journal and names `RESTORE.md`. `--undo` undoes each step, moves the 2.x-migrated db, storage and snapshot to `backups/opencode2-db-<ts>/` (never deleted), copies the frozen copy back (sha256 and count checked on a staged copy first; the permanent backup when the frozen copy has fewer sessions), moves a 2.x binary at `~/.opencode/bin` to `backups/opencode2-bin-<ts>/` and puts the 1.x binary back (sha256), and reports config files that differ from the 1.x snapshot without overwriting them. It never deletes the backup or the frozen copy and refuses while an `opencode` process runs (apply starts none, so there is nothing of ours to stop). `--uninstall` refuses while an upgrade is half done (an `applied` one is allowed with a warning, see Fixed). On a machine where lean-agents was never installed, apply creates a minimal `state.json` for the journal and `--undo` leaves it (journal `undone`, nothing else in it): harmless. The frozen copy must equal the backup or count at least its sessions (1.x only ever writes to the frozen db; checked at apply start, a refusal names the way out); a restore uses the frozen copy unless it counts fewer sessions than the backup. Journal writes go through a temp file and rename, and a failed save in a rollback is reported, not thrown. Windows: the 2.x install is not automated yet (VERIFY), so apply stops at `install2x` and rolls back unless 2.x is already installed by hand. Fault injection `LEAN_TEST_FAIL_AT=<step>` (fails right after that step; honored only with `LEAN_AGENTS_TEST=1`, no flag, not in `--help`). Proof: `tests/opencode-upgrade.test.mjs` (fakes) and `real-upgrade-opencode` (Linux: full apply and `--undo` on real 1.19 and 2.x, a 2.x start between them, one injected failure per step; Windows: refusals and rollback).

- `--upgrade-agent opencode --opencode1 [--dry-run|--yes]` (#80 part 2, P4, `scripts/lib/opencode1.mjs`): after `--backup`, copies the OpenCode 1.x binary to `<data>/lean-agents/opencode1/<version>/` and writes an owned shim `opencode1` (`opencode1` + `opencode1.cmd` on Windows) that sets `XDG_DATA_HOME` to the frozen copy and `XDG_STATE_HOME` to `opencode1/state`, so 1.x reads and writes only the frozen copy (the isolation proven in P1). The shim folder goes on PATH through a marked block in your shell rc file (an existing `.zshrc`, `.bashrc` or `.bash_profile`, else `.zshrc` or `.profile`), or on Windows the user PATH (HKCU, read and written unexpanded like `install.ps1`). Refuses without a frozen copy, with `--no-exec` (it runs `--version`), or over a user file named `opencode1` (never overwritten). State goes in `state.json` (`opencode1`); `--uninstall` removes the shim, the rc block or PATH entry and the binary copy, never the backup, the frozen copy or `opencode1/state`. `--undo` for this flag, and the full flow, come with P6. Tests: `tests/opencode1.test.mjs`, `tests/real-upgrade-opencode.sh` / `.ps1` (real 1.19.0: `opencode1 --version`, a new session lands in the frozen copy 3 -> 4, the live data hash is unchanged, undo; Windows from cmd and Git Bash).

### Fixed
- Preflight warning for a missing agent CLI writes to stderr under `--json` so stdout remains valid JSON (#179 PC run).
- `--everything --agents claude` (and others) now refuses before writing anything if the agent's CLI is missing from PATH (#179 PC run).
- `--uninstall` skips the `undo` of commands that had failed to run and only reported `ok: false`, allowing retry logic to complete without hanging (#179 PC run).
- `--adopt --undo` keeps other recorded work (upgrade, opencode1, files, commands) and removes `state.json` only when it is a pure adopt-only run. `--uninstall` preserves an existing `--adopt` record as an adopt-only state, so `--adopt --undo` still works after it (#179 PC run).
- The OpenCode 2 upgrade's DCP step now also pins the `tui.json` and `tui.jsonc` plugin entries if they exist, preventing a `spec-mismatch` health check warning (#307, #179 PC run).
- `--adopt --dry-run` (text and `--json`) now lists what `--yes` will do: which Node the pin goes into, re-registered MCPs, and the npm uninstalls, folders and stopgaps that need a yes. Before, it showed only the inventory rows, so `upgrade ... (Node 22.17.0)` read as an in-place upgrade and the uninstall of that copy was hidden (`--json` adds `apply`) (#179 PC run).
- `--upgrade-agent opencode --undo` after an upgrade that kept an OpenCode 2 installed by hand (the Windows route) restored the 1.x data under the 2.x binary and said both were back; the next `opencode` start would migrate the data again.
