# Architecture checkpoint: 0.7.0

First checkpoint (#59), 2026-11-06, on `main` at `c514353`. It questions the direction, not the details. Each question ends in **keep**, **change** or **spike** (a time-boxed prototype). The owner decides; this doc recommends. Commands run from the repo root; CI job-minutes are the sum of `completedAt - startedAt` over jobs that ran (skipped jobs left out).

## 1. Form: Node script, npm package or compiled binary?

| Fact | Command | Value |
| --- | --- | --- |
| Engine lines | `wc -l scripts/*.mjs scripts/lib/*.mjs scripts/lib/adapters/*.mjs \| tail -1` | 3512 |
| Adapter lines | `wc -l scripts/lib/adapters/*.mjs \| tail -1` | 562 |
| Adapters | `ls scripts/lib/adapters/*.mjs \| wc -l` | 7 |
| Unit tests, lines | `npm test`; `wc -l tests/*.test.mjs \| tail -1` | 120 tests (119 pass, 1 skip); 1804 lines |
| Real-binary test scripts | `ls tests/real-* \| wc -l` | 20 |
| Bootstraps | `wc -l install.sh install.ps1` | 65 + 120 |
| Dependencies, Node floor | `node -p "require('./package.json').dependencies"`, `.engines` | `@clack/prompts`, `jsonc-parser`; Node >= 22.20 |
| Tools that need Node anyway | `grep -n 24.15 scripts/lib/system.mjs`; `grep -c npx core/mcp.json` | Context Mode needs Node 24.15; Playwright MCP runs with `npx` |

A Go or Rust binary would remove the Node floor for the installer only. The tools it installs (Context Mode, Playwright MCP, GSD, skills) still need Node, so the user still installs Node. A rewrite costs 3512 engine lines plus 1804 test lines, and the 20 real-binary scripts would need new entry points. Windows already works from `install.ps1` and green Windows jobs. The real friction is `curl | bash` cloning the repo (audit N4, #65) and the 22.20 vs 24.15 gap (#44).

**Decision: change.** Publish to npm (#46) so `npx lean-agents` works everywhere, and keep the bootstraps thin. No binary: it would not remove Node, and it would cost a rewrite of everything the tests prove.

Owner decision (2026-11-06): accepted: npm (#46) plus thin bootstraps, no binary.

## 2. Script plus agent: is the split working?

| Fact | Command | Value |

| Updates ever filed | same with `--label "type: update"` | 4 (3 open) |
| `lean-update` skill size | `wc -l skills/lean-update/SKILL.md` | 35 lines |

Root causes: #72, #76 and #63 are in the script, #78 is upstream (Orca with OpenCode 1.19). None came from agent instructions. The 3 open updates (#50 to #52) are upstream releases the pin watch found. The `lean-update` skill only detects, explains, asks and backs up; every write goes through `scripts/lean.mjs` and is undone by `--uninstall`. Bugs live in the script, where tests can catch them, and the agent reads `--doctor --json` instead of guessing.

**Decision: keep.** The script stays the single source of truth; agents stay the middleware. Every bug so far was fixable and testable in the script.

Owner decision (2026-11-06): accepted: keep.

What costs more than it gives:

- **Two update channels.** `version-watch.yml` opens one issue per new upstream version, and since session 45 a green `ci-latest` opens a pin-bump PR. Both report the same news, and #50 to #52 stay open by hand. Keep one: the PR.
- **macOS jobs cancelled with no steps (#56).** They fail runs without testing anything. Keep macOS only where macOS behaviour is the point (session 21 rule 4) and find out why the runners don't start.
- **`ci-latest` has never gone green.** A daily check that has never passed teaches nothing. Get one green run, or turn the cron off until it can pass.
- **SPEC section 14 holds 311 lines of finished sessions** that every session reads first. Move the done session blocks to `docs/sessions-done.md` and keep one line each.

**Decision: change.** Drop the per-tool update issues for the bump PR, fix or trim the macOS jobs (#56), get `ci-latest` green, and archive the done sessions out of the SPEC.

Owner decision (2026-11-06): accepted: change.
