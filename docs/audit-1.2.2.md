## Findings and issues

- **LOW, accepted:** `scripts/lib/system.mjs` still passes `shell:` to `spawnSync` with an args array ([#475](https://github.com/estebanmr99/lean-agents/issues/475), DEP0190). It predates 1.2.1 (same 5 `shell:` sites) and is not exploitable in shipped code paths:
  - POSIX: `which()` runs `command -v <bin>` with `shell: true`, but every caller passes a literal or a pinned constant. The one variable case, `parallel.mjs` `which(argv[0])`, runs only when `agent !== 'custom'`, so `argv[0]` comes from `buildWorkerCommand` constants.
  - Windows: `useShell()` is true only for `.cmd` shims (npm, npx), with argv from pinned package specs and engine-computed paths. A `--home` with a space or `&` can be mangled, but only by the user's own input.
  - No path was found where file content, a state file, a download or network data reaches a `shell: true` argv.
  - This is a hardening and correctness issue (arguments concatenated unescaped), not an injection hole. Fix in 1.2.3 or 1.3.0 with a test that passes an argument containing a space and `&` through `run()`.
- **LOW, accepted:** `rtk init -g --opencode` may overwrite `plugins/rtk.ts`. The file is rtk's own output, not an owned lean-agents file, so the `file` kind does not apply. The command has a registered undo, the plan lists it, and `--upgrade-agent` only marks a 1.x-only `rtk.ts` as "regenerated by `--update`" and never writes it. A hand edit of that file is lost on `--update`; this is not yet stated in the docs.
- **LOW, accepted:** `rtkTooOld` and the doctor check read `rtk --version` of the first `rtk` on PATH. That binary is already trusted for `rtk init`, so the probe adds no new trust; the warning names its path (#472).
- **LOW, accepted:** the `ci-latest` run warns instead of failing on a hash mismatch (documented in `scripts/ci-download.sh`); the two new rtk entries inherit this. Every other run fails on a mismatch.
- **Checked, no defect:**
  - Downloads: the new `rtk-linux-x64` and `rtk-windows-x64` entries in `tests/ci-downloads.json` have an exact v1.2.0 release URL, a `sha256` and a `checked` date, and go through `scripts/ci-download.sh`, which deletes the file on a mismatch. The Linux hash equals the `linux-x64` hash in `core/pins.json`.
  - npm pins: all 13 npm integrity hashes in `core/pins.json` match `npm view <pkg>@<version> dist.integrity` on 2026-11-26. Pin ages rest on the pin-bump PR text.
  - Action pins: no new `uses:` lines; every `uses:` is pinned to a 40-character SHA.
  - Workflow safety: no `pull_request_target`; the only `${{ }}` in new `run:` lines is the static `matrix.major`.
  - Tests: `tests/real-opencode.sh` and `tests/real-opencode-rtk.ps1` use throwaway HOMEs with cleanup, bind `127.0.0.1`, and fail in CI when rtk is missing.
  - User files: the DCP `tui.json` edit uses the `json` kind with `legacy` values (exact versions only, only for a file that already lists DCP); `--uninstall` restores it (`tests/dcp-pins.test.mjs`, `tests/rtk-opencode2.test.mjs`, `tests/engine.test.mjs`).
  - Command injection: no new `shell: true`, `exec` or `execSync`; new argv entries are literals; file content only reaches string tests, never argv.
  - Secrets: new warning and doctor texts print versions and paths only.
  - Privacy: `bash scripts/check-private.sh` passes.
