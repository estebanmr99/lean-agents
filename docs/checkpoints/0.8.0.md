# Architecture checkpoint: 0.8.0

Second checkpoint (#59), 2026-11-12, on `main` at `f083fd9` (0.8.0 prep merged). Same rules as [0.7.0](0.7.0.md): each question ends in **keep**, **change** or **spike**; the owner decides, this doc recommends. Commands run from the repo root.

## 1. Writes outside fsops: is the boundary holding?

| Fact | Command | Value |
| --- | --- | --- |
| fsops (safe write path) | `wc -l scripts/lib/fsops.mjs` | 291 lines; new `remove` mode for `json` edits (#106) |
| New modules that act outside fsops | `wc -l scripts/lib/{adopt,agent-lifecycle}.mjs` | 467 + 163 lines |
| Actions outside fsops, owner-approved | `.git` plans for #106 and #80 | `npm uninstall -g` of an old copy, delete a backed-up duplicate skill, vendor installers (pinned + sha256), delete recorded install files (sha match) |

0.8.0 is the first release that deletes things: old npm copies, duplicate skill folders, files an agent installer created. Each one is opt-in (`--confirm-removals` or a menu), backed up or recorded with a hash first, and undone by `--adopt --undo` / `--uninstall-agent`. `real-adopt` proves the byte-exact undo on Ubuntu and Windows. `--install-agent` refuses to touch an OpenCode 1.x install.

**Decision: keep.** fsops stays the only silent write path; anything else needs a confirm, a backup or hash record, and an undo with a real-binary job.

## 2. OpenCode 1.x to 2.x: can the two live side by side?

| Fact | Source | Value |
| --- | --- | --- |
| Config dir | B0 spike (#143), run 43350726437 | shared `~/.config/opencode`; each version ignores the other's keys |
| Data dir | same | shared `~/.local/share/opencode`; the first 2.x start migrates the 1.x db in place (tables 20 to 29, migrations 38 to 59) |
| v2 installer | same | writes only `~/.opencode/bin/opencode`; no rc or HKCU Path change |

The guided upgrade (#80 part 2) cannot simply install 2.x next to 1.x: 2.x rewrites the 1.x sessions. The owner does not want a permanent second data path for 2.x, because 1.x will be removed later.

**Decision: change.** Move the guided upgrade to 0.9.0 with a new plan: 2.x keeps the default dirs and migrates after a permanent session backup; `opencode1` runs 1.x on a frozen copy. Before anything runs on the work PC, a read-only inventory there (#145) and a CI fixture shaped like it must prove that every global skill, command, local plugin and MCP server carries over.

Most red PR runs in 0.8.0 were not code: HTTP 429 on a download, a GitHub API rate limit in `real-winget`, and a stale run queued behind the same branch. The spike job runs only on `workflow_dispatch`.

**Decision: keep**, with one small change: a job that fails on a rate limit or a runner cancel is re-run once before anyone reads its log.
