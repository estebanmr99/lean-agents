## Windows

- `install.ps1` runs on PowerShell 5.1 and 7 and needs no admin rights.
- Tools come from winget (`rtk-ai.rtk`, `astral-sh.uv`). `real-winget` installs both without a TTY: rtk 1.1.0 and uv 0.13.6 on 2026-10-31.
- Without winget, extract `rtk-x86_64-pc-windows-msvc.zip` into `%USERPROFILE%\tools\rtk`; `install.ps1` adds it to the user PATH.
- No directory junctions are needed: the Skills CLI installs into `~/.claude/skills` and `~/.agents/skills`, and OpenCode reads `~/.agents/skills`.
- `rtk init` writes to the OS profile folder, not `USERPROFILE`. It only matters when testing with a temp `USERPROFILE`.
- OpenCode 2 on Windows: `opencode.ai/v2/install` runs through Git Bash, installs `opencode.exe` into `%USERPROFILE%\.opencode\bin` and only edits `~/.bashrc` / `~/.bash_profile` (`--no-modify-path` skips that), so PowerShell needs the user PATH entry added by hand. Verified on v2.2.5 (Authenticode valid). `npm i -g opencode-ai` installs 1.x, not 2.x. `install.ps1` finds that folder when `opencode` is not on PATH. Source: real install, #32, 2026-11-05.
- Agent shell (#124, follow-up proven): the install summary and `--doctor` say whether Git Bash was found (`MSYSTEM` set, or `bash.exe` under `Program Files\Git\bin`); lean-agents now also sets OpenCode's `shell` key to that path by default on Windows (`--shell default` opts out; a `shell` you already set is kept). **Proven** on `windows-latest` with the real `real-opencode-shell` CI job (jobs 131467661473 for 1.19.0, 131467661406 for 2.2.5; date 2026-11-12), using a local mock OpenAI-compatible LLM (`tests/fixtures/mock-llm.mjs`) so the one bash/shell tool call needs no login: `shell` set to an absolute Git Bash path makes the tool run there (`$0`/`SHELL0` names `bash`) even with Git's own folders off PATH, for both 1.19.0 (tool name `bash`) and 2.2.5 (tool name `shell`). Without the key, or with `shell` set to `powershell.exe`, the probe's `MSYSTEM`/`$0` both come back empty on both majors — consistent with PR 16069's claim that Windows defaults away from Git Bash, though the probe cannot tell PowerShell and cmd.exe apart from that alone. The Git Bash case also ran through the real installer (`install.ps1 -NoCore -NoTools`), not a hand-written config, confirming the shipped adapter writes the same path. Precedence against `OPENCODE_GIT_BASH_PATH` and `opencode debug config` printing only sources on 2.2.6 stay **VERIFY**; neither blocks this default.
- The runner image has no winget; `real-winget` adds it with `Repair-WinGetPackageManager`.

## Staying on OpenCode 1.x

lean-agents never installs or upgrades OpenCode: the engine only writes config for the OpenCode you already have, and `--doctor` says "OpenCode 1.x: supported; lean-agents will not upgrade it". `tests/opencode-guard.test.mjs` fails if any install, `--update`, `--migrate` or `lean-update` plan contains a command that installs or upgrades OpenCode. Moving from 1.x to 2.x is your own step.

Why back up first: the session history lives in a database, `opencode.db`, and OpenCode 2 reportedly does not carry your old sessions over (owner report, 2026-11-06; **VERIFY** against the OpenCode 2 release notes). Copy it (never move it) before any major upgrade.

| Item | Where | Status |
| --- | --- | --- |
| Data folder and `opencode.db` on macOS and Linux | `~/.local/share/opencode/opencode.db`; `OPENCODE_DB` overrides it | Docs ([troubleshooting](https://opencode.ai/docs/troubleshooting/)), 2026-11-06 |
| Data folder on Windows | `%USERPROFILE%\.local\share\opencode` | **VERIFY**: only a user report in the upstream tracker, no docs |
| `XDG_DATA_HOME` handling | not in the docs | **VERIFY** |
| Exact paths on your machine | `opencode debug paths` (all paths) | Docs ([CLI](https://opencode.ai/docs/cli/)), 2026-11-06; the `db` selector is **VERIFY**; `real-opencode-v1` prints the output (non-fatal) |
| User config | `~/.config/opencode/` (`opencode.json` or `opencode.jsonc`) | Docs ([config](https://opencode.ai/docs/config/)), 2026-11-06 |
| Version that introduced `opencode.db` | unknown (the [1.2.0 changelog](https://opencode.ai/changelog/v1.2.0) says "Revert to SQLite database implementation") | **VERIFY** |

Back up (macOS, Linux; close OpenCode first). This copies and removes nothing. The copy can hold your provider logins, so keep it private:

```bash
b="$HOME/opencode-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$b" && chmod 700 "$b"
cp -R ~/.local/share/opencode "$b/data"   # includes opencode.db; run `opencode debug paths` if yours differs
cp -R ~/.config/opencode "$b/config"
echo "Backup in $b"
```

On Windows, copy the same two folders in Explorer. Keep the backup until you are sure you do not need your old sessions.

A community script that downgrades 2.x back to 1.19 exists ([gist](https://gist.github.com/iarna/5d030e28c56c137f489a9d7ad12aa74a), SQL; check its own text for platforms). It is community code, use at your own risk. lean-agents has not reviewed it and never runs it.

Spike for #80 (job `spike-opencode-side`, PR #143, CI run 43350726437, 2026-11-13; ubuntu-latest and windows-latest, throwaway HOME, 1.19.0 from npm and 2.2.5 from the pinned installer with `--no-modify-path`). Both spike jobs passed. A local macOS run (not in CI) saw the same numbers.

- **V1 paths:** `opencode debug paths` gives the same config dir (`~/.config/opencode`) and data dir (`~/.local/share/opencode`, `opencode.db`) for both binaries, on Linux and Windows (under the throwaway profile).
- **V2 data:** the first 2.x start rewrites the 1.x `opencode.db` in place: 20 tables / 38 migrations before, 29 tables / 59 migrations after (same on Linux and Windows; local macOS run too). 1.x still opened the upgraded db afterwards (Linux exit 0; on Windows `session list` hit the 90 s limit both before and after, the db was created and readable). 2.x also rewrites `service.json` in the config dir. It left `opencode.jsonc` and `tui.json` alone. Not measured: whether 1.x can still write sessions to the upgraded db.
- **V3 keys:** each binary ignores the other's keys. 1.x read the 2.x-only and the mixed file without error (it dropped `agents`, `plugins`, `compaction.buffer`, `update`); 2.x dropped `agent`, `plugin`, `compaction.reserved`, `autoupdate`. One file holding both key sets works for both (Linux; Windows exit 0, keys not captured).
- **V4 installer:** the v2 installer wrote only `~/.opencode/bin/opencode` (+ its data dir logs). With `--no-modify-path` it did not touch `.bashrc`, `.zshrc` or `.profile`; on Windows the HKCU user Path was unchanged.
- **Layout answer: I (isolate).** Config could be shared, but 2.x migrates the shared 1.x database, so a 1.x user's sessions cannot be left untouched without giving 1.x its own data dir. Next (PR B): prove isolation (`XDG_DATA_HOME` or equivalent for the `opencode1` shim) before any upgrade path ships.
